# Практическая работа 02. Вариант A

Среда: Windows, Uniform Server, PHP 8.3 (mbstring включён).
Веб-корень: `public`.
Базовый URL: `http://localhost:8088/`

## Информация о сдаче
* **Вариант:** A (Допустимые темы: php, http)
* **PHP:** Версия 8.3 (успешно проверено через health.php)
* **Адрес локального хоста:** http://localhost:8088/

## Реализованные задачи
* **P02-SCALAR (`app.php`):** Реализована функция безопасного чтения `textField`. Добавлена защита от передачи массивов, строгая проверка корректности кодировки UTF-8 и нормализация данных с помощью `trim`.
* **P02-VALIDATE (`app.php`):** Реализована функция полной серверной валидации `validateRegistration`. Проверяются ограничения по длине имени (в символах через `mb_strlen`), объёму email (до 120 байт через `strlen`), строгому формату количества мест (одна цифра 1–5), выбору темы из своего варианта и наличию согласия. Ошибки собираются одновременно по всем полям, а верные значения сохраняются в форме после ответа 422.
* **P02-ESCAPE (`app.php`):** Реализована функция HTML-экранирования `h` с флагами `ENT_QUOTES | ENT_SUBSTITUTE` для защиты от XSS-уязвимостей в тексте и атрибутах.

## Результаты самопроверки
Все тесты из методички успешно пройдены:
1. **Успешный сценарий:** При отправке корректных данных сервер возвращает HTTP-статус `200 OK` и страницу с подтверждением предпросмотра данных.
2. **Множественные ошибки:** При отправке пустых или некорректных данных сервер возвращает HTTP-статус `422 Unprocessable Entity`, выводит сообщения об ошибках под каждым неверным полем, сохраняя при этом ввод в правильно заполненных полях.
3. **Безопасный вывод:** Теги, кавычки и амперсанды в полях успешно экранируются и выводятся браузером как обычный безопасный текст.
4. **Контракт маршрутов:** Прямой GET-запрос на `/register` возвращает ошибку `405 Method Not Allowed` с заголовком `Allow: POST`.
